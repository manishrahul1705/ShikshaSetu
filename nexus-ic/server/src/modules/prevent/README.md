# NEXUS PREVENT — S4 contract

Synthetic demonstrator. Advises only: never submits/merges/rejects cases or changes their status, priority, routing, owner or lifecycle. No remote matching, embedding, translation or AI service. The semantic-labelled signal is **local character n-gram similarity**, not a trained semantic model. Missing remedy, shared-entity or period evidence contributes zero with a counter-reason, never invented data. Source weights are exactly issue 25, time window 15, category 10, document or subject 15, remedy 10, shared entities 10, semantic 15.

Full F23/F24/E01, C1-C5, official overlap thresholds, detailed identity gate, worked 93.75 example and X01-X04 remain BLOCKED-SOURCE. The implemented identity boundary is limited to the explicitly supplied exact PID + resolveIdentity supporting-ICID contract.

## Public API (index.js)

- `getRules()` dynamically calls S2 `getActiveRule('OVERLAP_DETECTION')` from rulebook/index.js. Adapter expects `{ status: 'approved', version, body: { overlapThreshold: (0,100], minIssueSimilarity: (0,1], gramSize: positive integer, freshnessMs: positive milliseconds } }`. No client-supplied rules accepted. A DEMO version is valid only in APP_MODE=demo. An absent/unapproved rule falls back to defaults only in demo; production gives unconfigured POLICY_NOT_CONFIGURED. Broken adapter gives RULEBOOK_UNAVAILABLE, not fabricated CLEAR. S2 owns approval and its immutable version history; align this adapter when its agreed schema lands.
- `matchCases(a, b, rules?)` returns advisory CLEAR/REVIEW/UNKNOWN, score, seven weighted contributions, fixed reason/counter-reason codes, identity and rule version. Different PIDs never match; ICID conflict forces REVIEW. The optional rules parameter is server-only, for deterministic internal use/tests; routes cannot supply it.
- `signals(a, b, rules)` returns the seven `{ name, weight, value, contribution, reason }` entries. Supported evidence fields: institutionPid, institutionIcid/icidSnapshot.icid, narrative, category, subCategory/subjectKey, period `{start,end}`, documentIds, remedy and entities. Existing cases without optional evidence report its absence.
- `localSemantic(a, b, size=3)` gives local NFC/case-folded Unicode-character n-gram Jaccard overlap in [0,1]; script-independent, no network. `WEIGHTS` is the frozen source-weight map.
- `checkSimilar(user, draft)` verifies reporter and institution, evaluates canAccessCase for every candidate, runs matching across open/past cases at the exact PID, persists a hash/minimal check and audits. Own earlier case IDs are returned only after ownership + access checks. Third-party match returns only the constant generic notice, never text, score, reporter ID, Master Case ID, userId or identity evidence.
- `chooseSimilar(user, {checkId, choice, caseId?})` accepts continue/view/cancel, checks reporter ownership, re-authorizes view of an actually shown own case, persists choice and audits. Every choice remains advisory; the ordinary S1b submit route is independent.
- `checkAction(user, {caseId, actionType, details:{subject,direction?}})` rechecks target scope, detects exactly the three SPEC-named conditions under synthetic DEMO-PREVENT-v1 (repeat document request, overlapping same-subject action across bureaus, ALLOW vs DENY instruction), logs the result and creates an alert for REVIEW/UNKNOWN. Missing action data or any stale/future timestamp gives UNKNOWN. No policy/owner/status side effect.
- `actionSubject(details, actionType)` returns an opaque SHA-256 digest of normalized subject; INSTRUCTION prefixes the enumerated synthetic ALLOW/DENY direction. Never pass arbitrary text as stored subjectKey. This is a demonstrator vocabulary, not C1-C5 or natural-language legal interpretation.
- `proceedAction(user, checkId)` re-authorizes original officer/target and records the officer's proceed choice even for REVIEW/UNKNOWN, adding a case_actions record; it never executes a case lifecycle action. Returns proceeded=true only after attributed audit. Retry of an already recorded check does not intentionally add another action. Concurrent multi-process idempotency requires a future transaction/idempotency contract.
- `listOverlaps(user, institutionPid?)` evaluates current canAccessCase for every candidate and compares same-PID pairs; serializes only pairs where both cases are accessible, plus a count of restricted entries for matches involving an accessible case. No raw case/narrative/reporter fields are returned. Logs the check; production unconfigured gives UNKNOWN.
- `listAlerts(user)` returns only the logged-in officer's alerts, re-authorizing the linked case at each poll. Returns no original action details or actor/reporter identity.
- `coSign(user, caseId)` permits only a verified student whose vault-derived institution PID equals the target's, excludes the target's reporter, and enforces one reporter/case via a database unique index. This narrow endorsement capability does not grant access to the case narrative. It writes only co_signs and an audit record; it never mutates cases or matching inputs.
- `coSignSummary(user, caseId)` returns **only `{count}`** to authorized officer roles; a student receives only eligible/signed flags. No names, user IDs or reporter IDs are serialized.
- `CaseAction` is the model below, exposed for S3. S3 must use current canAccessCase and append attributed audit for each write; never write complaint/identity text into these fields.

Internal access helpers (access.js): `uid(user)` resolves the authenticated account ID; `fail(status,code)` creates safe errors; `hash(value)` hashes ephemeral input; `audit(user,action,targetId,meta?)` appends safe attributed PREVENT events; `caseAccess(user,row)` enriches server context with S1a reporterId then calls canAccessCase; `readCase(user,id)` resolves and authorizes a case, otherwise returns an audited 404. `officerRoles` is the exact /review role list. Models additionally expose SimilarityCheck, CoSign, ActionCheck, PreventAlert and ACTION_TYPES for internal services/tests.

S1a extension: `getVerifiedInstitutionPid(userId)` returns only a PID from a verified student's encrypted vault evidence, or null for unverified/non-student/missing evidence. The synthetic fixture maps DEMO-INSTITUTION-1 to 1-1000000001; it is not an official institution claim. PREVENT never reads identity_vault itself.

## Collections and S3 case_actions schema

`case_actions`: `{ caseId: ObjectId, institutionPid: String, bureau: String, actorId: String, actorRole: String, actionType: DOCUMENT_REQUEST|INSTRUCTION|INSPECTION|NOTICE|OTHER, subjectKey: String, at: Date }`, with timestamps. All fields required. subjectKey MUST be produced by actionSubject; no narrative, names, document text or free-text instructions. Records are observations of human choices, not decisions by PREVENT. S3 owns subsequent officer workflows; it must not modify this schema except via the agreed plugin mechanism.

`intake_similarity_checks`: draftHash, reporterId, shownHints (own Master Case IDs or GENERIC), userChoice pending/continue/view/cancel; no third-party text. `co_signs`: caseId/reporterId with unique compound index, private service storage only. `prevent_action_checks`: target, officer, enumerated proposed action and subject digest, result and proceeded/action reference, no details. `prevent_alerts`: target/check/recipient/result/fixed reason codes, never narrative.

## Routes and UI

All routes authorize on their own route layer and additionally check the live account. POST `/api/v1/grievances/check-similar`, POST `/api/v1/grievances/check-similar/choice` for complainants; POST `/api/v1/prevent/check-action`, POST `/api/v1/prevent/check-action/:id/proceed`, GET `/api/v1/prevent/overlaps`, GET `/api/v1/prevent/alerts` for supervisor/competent_authority/regional_officer/bureau_officer; POST `/api/v1/cases/:id/co-sign` for students, GET same path for students/officers. Responses use no-store and safe error codes only.

`/review` combines overlap banner, pair contributions, action form and officer alerts. `/prevent/back` is the student endorsement entry page; knowing an ID never grants narrative access. Stage 1 panel is inserted into the existing grievance preview, and banners into Dashboard and Institution360 with one import/JSX insertion each. Every component has English/Hindi strings. Alerts/banner poll every 15 seconds (DEMO), no sockets. Buttons remain usable during UNKNOWN/offline advice; a failed log is shown honestly, not claimed recorded.

## DEMO values / limitations

defaults.js: DEMO-OVERLAP-v1 threshold 55/100, minimum issue overlap .30, character grams 3; DEMO-PREVENT-v1 freshness 24h, polling 15s, opposing instruction directions ALLOW/DENY. Each labelled **not from source; replace with 23 Oct PDF values**. These do not claim the missing source thresholds, detailed identity gate, C1-C5 or 93.75. Case reads are filtered at serialization; private internal matching may yield only the expressly permitted generic existence hint or restricted count. API-wide authorization is not replaced by UI filtering. No dependencies added.

Demo seed entry is owned by S4 (seed.js), not injected into another phase's seed/reset files. Full verification: `$env:TEST_MONGODB_URI="mongodb://127.0.0.1:27017"; npm test`. Never change S0 test setup or skip a failing test.

`seedPreventDemo()` (seed.js) creates only missing synthetic demonstration institution/case fixtures in a connected *_demo database and audits them. It reuses N48 generated institution details, S1a seeded reporter accounts, and S1b's atomic case-ID helper. The two preassigned synthetic case fixtures demonstrate the existing RB office context; this is fixture construction, not a PREVENT routing decision or mutation of existing cases. Run after guarded reset: `node server/src/modules/prevent/seed.js`. The CLI reads root .env without printing keys. S0 configuration's demo default is used consistently when APP_MODE is absent; explicit production never enables fallback. For local dev, inherit root .env (including vault key) into npm run dev; no secret is written or logged by S4.
