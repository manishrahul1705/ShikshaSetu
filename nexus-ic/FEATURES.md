# FEATURES.md: traceability checklist for NEXUS-IC

Every ID in the solution has exactly one row. Nothing may be removed, merged or renumbered.
Machine-checked by `node scripts/trace-check.js`.

## Status values
- `TODO`: not started.
- `IN-PROGRESS`: being built.
- `DONE`: built AND "Built in" lists real file paths AND a test titled `[<ID>] ...` exists and passes. Never mark DONE otherwise.
- `GAP`: cannot be done; the Notes column must say why. (Definition of done allows "listed as a gap".)
- `BLOCKED-SOURCE`: the defining text is not in the repo yet (23 Oct PDF or N36â€“N45). Do not build or invent. Only build what the "Known" hint and docs/SPEC.md state.
- `PLANNED-P2`: P2 item; only the interface/stub and a doc note are built.
- `NOT-ADOPTED`: rejected addition; never build.

## Rules for the agent
1. Change only the Status, Built in, Proved by and Notes columns. Never edit ID, Title, Source, Pri or Stage.
2. "Built in" = comma-separated repo-relative paths. "Proved by" = test IDs; the row's own ID test `[<ID>]` is always required for DONE.
3. Stages marked "chosen by Claude" are suggestions where the doc's roadmap (Section 18) is silent. The roadmap itself is unchanged.
