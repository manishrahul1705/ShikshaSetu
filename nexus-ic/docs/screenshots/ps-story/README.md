# Problem-statement browser evidence

The local showcase contains fictional records. No real institution or complainant data is used. The shared demo database was not reset.

Run `npm exec playwright -- test --config=playwright.ps.config.js` for three consecutive rehearsals. The runner uses installed Chrome with a fresh profile and the dedicated local services on ports 4317/5317. It does not reset the database. `playwright.ps-audit.config.js` checks the new pages for every permitted role at 1366 × 768 and 390 × 844.

Each run directory contains:

1. Inline PREVENT warning and existing-document counter-signal.
2. Combined request with separate office items.
3. Versioned document locker.
4. Student next-step tracking.
5. Mobile student tracking.
6. Monthly pendency report.
7. Coverage matrix.
8. Scripted versus recorded comparison.
9. Mobile comparison.
10. Bureau workload and leave.

`checks.json` records measured readiness and page errors. `monthly.csv` and `monthly.pdf` are actual authenticated exports with N55 attribution and trace markers. Input values and protected text are masked before screenshots. The rehearsal also checks that student sessions cannot access officer reports, combined requests, locker administration or coverage.

Video is currently unavailable: the installed Playwright expects `ffmpeg-1013/ffmpeg-win64.exe`, which is absent. No binary was downloaded under the phase's no-install/no-download constraint. A passing screenshot rehearsal must not be described as video proof.

Monthly reporting preserves evidence gaps: historical Closed records without imported PROOF evidence are explicitly marked incomplete. The comparison's left column is an illustrative sequence; the right counts issued combined covers, separate N70 queries, PREVENT flags and accepted TRACE transfers. Neither side measures real-world savings.

The development phase report is archived outside the repository. Run counts and timing evidence remain in the per-run checks and reporter files indexed above.
